## 1. Backend — Screener: REIT columns and filters

The roadmap's "switch columns for REIT rows" instruction has no GAAP column to switch *from* here — `ScreenerResultItem` never carried P/E, Debt/Equity, or payout ratio in the first place (confirmed: only `compositeFairValue`/`marginOfSafety`, which come from `ValuationResult`'s DCF/Graham/DDM composite and are untouched by RM2). So this group **adds** REIT columns/filters rather than replacing existing ones — the Fair Value/MoS columns keep showing the DCF-based composite for every sector, REIT included, exactly as before.

1. `ScreenerResultItem`: add seven nullable `BigDecimal` fields at the end of the record — `ffoPerShare`, `affoPerShare`, `priceToFfo`, `priceToAffo`, `netDebtToEbitda`, `interestCoverageEbitda`, `affoPayoutRatio` — same names as the `RatioSnapshot` columns RM2 added, so the frontend type mirrors the backend field-for-field with no renaming.
2. `ScreenerService.runDataQuery`'s `query.multiselect(...)` ([ScreenerService.java:159-175](backend/src/main/java/it/mazzoni/vis/screener/ScreenerService.java#L159)): add the seven `rs.get("...").alias("...")` selections (the `rs` root is already in scope, already joined to the correct TTM row via the existing `maxRatioDate` subquery predicate — no new join needed).
3. `ScreenerService.toItem`: read the seven new `Tuple` values (`t.get("ffoPerShare", BigDecimal.class)`, etc.) and pass them into the `ScreenerResultItem` constructor. Non-REIT rows read back `null` for all seven automatically (RM2 never populates them outside `SectorClassifier.isReit`) — no branching needed here, mirrors how `piotroskiScore`/`altmanZone` already degrade to `null` for symbols missing that data.
4. `ScreenerRequest`: add three nullable `BigDecimal` filter fields — `maxPriceToFfo`, `maxNetDebtToEbitda`, `maxAffoPayoutRatio` — appended after the existing `sharesOutstandingTrend` field. Add a new backward-compatible telescoping constructor (the record already has one, added when `moatStrength`/`sharesOutstandingTrend` were introduced — follow that exact precedent: old-shape constructor delegates to the new canonical one with the three new fields defaulted to `null`) so any existing caller/test constructing the old 18-arg shape keeps compiling.
5. `ScreenerService.normalize`: thread the three new fields through unchanged (no `clean()`/enum validation needed — they're plain `BigDecimal` thresholds, same treatment as `maxDebtToEquity`). Do **not** add a `validatePercentThreshold` call for any of the three: `priceToFfo` and `netDebtToEbitda` are multiples (not percentages, same treatment as `maxDebtToEquity`), and RM2 persists `affoPayoutRatio` as a raw ratio (e.g. `1.6225` = 162.25%, confirmed against `O`'s live-verified value in `specs/2026-09-02-rm2-sector-metric-profile/validation.md`), not a 0–1 fraction requiring the `/100` conversion `minDividendYield`/`minRoic` use — treat it exactly like `maxDebtToEquity`.
6. `ScreenerService.buildPredicates`: add
   ```java
   if (request.maxPriceToFfo() != null) predicates.add(cb.lessThanOrEqualTo(rs.get("priceToFfo"), request.maxPriceToFfo()));
   if (request.maxNetDebtToEbitda() != null) predicates.add(cb.lessThanOrEqualTo(rs.get("netDebtToEbitda"), request.maxNetDebtToEbitda()));
   if (request.maxAffoPayoutRatio() != null) predicates.add(cb.lessThanOrEqualTo(rs.get("affoPayoutRatio"), request.maxAffoPayoutRatio()));
   ```
   **Document explicitly** (Javadoc comment above these three lines, plus `requirements.md` → Decisions): setting any of these three filters implicitly restricts results to REIT-classified securities, because every non-REIT row's `priceToFfo`/`netDebtToEbitda`/`affoPayoutRatio` is `null` and a `<=` comparison against `null` excludes the row — the exact same implicit-scoping behavior `minRoic`/`maxDebtToEquity` already have for symbols missing that ratio. Not a new class of behavior, but worth calling out since these three filters are REIT-only by construction rather than incidentally.
7. `ScreenerService.sortExpression`: currently takes `(field, sec, vs, vr)` only — add `rs` as a fourth parameter (threaded from both of its two call sites, `runDataQuery` and nowhere else) and a `case "priceToFfo" -> rs.get("priceToFfo");` branch. Add `"priceToFfo"` to `VALID_SORT_FIELDS`.

   ```java

           BigDecimal ffoPerShare, String ffoFormula,
           BigDecimal affoPerShare, String affoFormula,
           BigDecimal priceToFfo, BigDecimal priceToAffo, String valuationMultipleFormula,
           BigDecimal netDebtToEbitda, BigDecimal interestCoverageEbitda, String safetyFormula,
           BigDecimal affoPayoutRatio, String payoutFormula,
           String availabilityStatus, String availabilityMessage
   ) {
       static final String FFO_FORMULA = "FFO per share = (Net Income + Depreciation & Amortization) / Shares Outstanding — a D&A-only approximation of the full NAREIT formula (gains/losses on real-estate sales are not isolable from FMP's data; see specs/sector-aware-valuation-metrics.md §5).";
       static final String AFFO_FORMULA = "AFFO per share = FFO per share − recurring capex per share, where recurring capex is estimated as Depreciation & Amortization × 70% (the platform's existing maintenance-capex assumption, reused from the DCF owner-earnings calculation) — a known conservative-AFFO understatement for net-lease REITs, see specs/2026-09-02-rm2-sector-metric-profile/validation.md → Known Risks.";
       static final String VALUATION_MULTIPLE_FORMULA = "P/FFO and P/AFFO = current price ÷ FFO or AFFO per share — REIT-appropriate substitutes for P/E; lower is cheaper relative to the metric's own history.";
       static final String SAFETY_FORMULA = "Net Debt/EBITDA = (Total Debt − Cash) / EBITDA; EBITDA Interest Coverage = EBITDA / Interest Expense — substitutes for Debt/Equity and generic interest coverage. Uses raw (unadjusted) EBITDA, not a REIT's own EBITDAre adjustment, so this reads more conservatively than a company-reported leverage figure — see specs/2026-09-02-rm2-sector-metric-profile/validation.md → Known Risks for a live example (O: ~9.1× here vs. ~5.5× company-reported).";
       static final String PAYOUT_FORMULA = "AFFO Payout Ratio = (GAAP Payout Ratio × EPS) / AFFO per share — substitutes for EPS payout ratio as the dividend-sustainability check for this sector.";
       // from(RatioSnapshot ratio) below — null-safe per-field, INSUFFICIENT_DATA when every field is null
   }
   ```
