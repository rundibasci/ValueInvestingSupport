## Known Risks (carried forward or introduced by this phase)

- **Historical `ValuationResult` rows generated before this phase keep their old, GAAP-based `compositeFairValue`/`marginOfSafety`** — confirmed live (the pre-RM5 `O` rows in the same database still show `49.98`/`-23.05` unchanged) — only new valuation runs after merge see the corrected figure. Not a backfill target this phase, same posture as every prior RM/TA6 fix.
- **The AFFO-based fair value is still a relative-multiple estimate (median own-history P/AFFO × current AFFO/share), not a true intrinsic-value model** — it answers "is this REIT cheap or expensive versus its own recent past," not "what is this REIT structurally worth," which remains permanently out of reach without property-level cash flow data (RM1's confirmed finding). This is a real, disclosed limitation of the substitute, not a hidden one.
- **A REIT with fewer than 3 years of trading history will show `INSUFFICIENT_DATA`/null Margin of Safety indefinitely until enough `RatioSnapshot` history accumulates** — by design (Decision 5), but a real UX gap worth flagging: such a REIT had a GAAP-based (if wrong) number before this phase, and now has none at all.
 **No automated check exists for whether the AI's prose reasoning about a now-correct `marginOfSafetyPercent` is itself sound** — same disclosed gap RM4/TA6 both carried forward; out of scope for a valuation-engine correctness fix with no prompt change attached.
