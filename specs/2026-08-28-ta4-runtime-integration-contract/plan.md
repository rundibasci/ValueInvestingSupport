# TA4 — Implementation Plan

## 1. Persistence

1. Add `backend/src/main/resources/db/migration/V27__investment_thesis_result.sql`: table `investment_thesis_result` with columns `id BIGSERIAL PRIMARY KEY`, `security_id BIGINT NOT NULL REFERENCES security(id)`, `request_id UUID NOT NULL UNIQUE`, `requested_by_user_id BIGINT NOT NULL REFERENCES app_user(id)`, `model_id VARCHAR(128) NOT NULL`, `model_version VARCHAR(64) NOT NULL`, `prompt_version VARCHAR(64) NOT NULL`, `input_snapshot JSONB NOT NULL`, `output_json JSONB`, `classification VARCHAR(32)`, `confidence NUMERIC(3,2)`, `human_review_required BOOLEAN`, `status VARCHAR(32) NOT NULL`, `error_code VARCHAR(64)`, `error_message TEXT`, `raw_output_available BOOLEAN NOT NULL DEFAULT FALSE`, `latency_ms INTEGER`, `generated_at TIMESTAMP`, `created_at TIMESTAMP NOT NULL DEFAULT now()`.
2. Indexes: `idx_thesis_security_generated (security_id, generated_at DESC)`; partial `idx_thesis_review_queue ON investment_thesis_result (generated_at DESC) WHERE status = 'HUMAN_REVIEW_PENDING' OR output_json -> 'dataWarnings' <> '[]'::jsonb` (adjust predicate to whatever JSONB emptiness check Postgres 16 accepts cleanly — verify with `EXPLAIN` during implementation, fall back to a plain non-partial index plus a `WHERE` clause in the repository query if the partial-index predicate proves awkward).
3. Add JPA entity `it.mazzoni.vis.thesis.InvestmentThesisResult` (immutable — no setters beyond what Hibernate requires, no update path anywhere in the codebase) and `ThesisStatus` enum (`GENERATING`, `READY`, `FAILED`, `HUMAN_REVIEW_PENDING`).
4. Add `InvestmentThesisResultRepository extends JpaRepository<InvestmentThesisResult, Long>`: `Optional<InvestmentThesisResult> findTopBySecurityIdOrderByGeneratedAtDesc(Long securityId)`, `Optional<InvestmentThesisResult> findByRequestId(UUID requestId)`, `List<InvestmentThesisResult> findByStatusOrDataWarningsNotEmptyOrderByGeneratedAtDesc(...)` (exact query shape depends on how `dataWarnings` ends up queryable from JSONB — a `@Query` native/JPQL expression is expected here, not a derived-name method, given the JSONB predicate).
5. Test: `InvestmentThesisResultRepositoryTest` (`@DataJpaTest`) — insert two rows for the same security at different `generated_at`, confirm `findTopBySecurityIdOrderByGeneratedAtDesc` returns the newer one; confirm no update/save-over-existing-id path exists in the repository interface (a structural assertion, not just a runtime test).

## 2. Runtime Contract Types

1. Add package `it.mazzoni.vis.thesis`. Records: `ThesisGenerationRequest(UUID requestId, String modelVersion, ThesisInput input)`; `ThesisInput` mirrors `thesis-input.schema.json`'s field set exactly (reuse whatever DTO already carries `marketPrice`/`intrinsicValue`/... from the valuation/scoring modules if one already exists with the identical field set — check `it.mazzoni.vis.valuation`/`it.mazzoni.vis.scoring` before introducing a duplicate type).
2. Sealed interface `ThesisGenerationResult` permits `ThesisGenerationSuccess(UUID requestId, String modelId, String modelVersion, String promptVersion, int latencyMs, ThesisOutput output)` and `ThesisGenerationFailure(UUID requestId, ThesisErrorCode errorCode, String errorMessage, boolean rawOutputAvailable)`. `ThesisOutput` mirrors `thesis-output.schema.json` (`classification`, `confidence`, `summary`, `bullCase`, `bearCase`, `keyRisks`, `keyAssumptions`, `invalidationConditions`, `dataWarnings`, `humanReviewRequired`).
3. `ThesisErrorCode` enum: `SCHEMA_VALIDATION_FAILED`, `TIMEOUT`, `INPUT_SCHEMA_INVALID`. (`HUMAN_REVIEW_REQUIRED` is deliberately *not* an error code here — it's a successful `ThesisGenerationSuccess` whose `output.humanReviewRequired()` is `true`, routed to the review queue by the persistence layer, per TRAIN-12.2's own distinction.)
4. Test: `ThesisGenerationResultTest` — exhaustive `switch` over the sealed interface compiles (a compile-time check that both variants are handled everywhere a `ThesisGenerationResult` is consumed).

## 3. `InvestmentThesisClient`

1. Confirm the current Java SDK for calling Vertex AI Gemini against live Google Cloud documentation (do not assume the Python `google-genai` package name/version carries over to Java — verify the Maven coordinate, e.g. `com.google.cloud:google-cloud-vertexai` or a Java `google-genai` artifact if one now exists, whichever is current and actively maintained at implementation time) — record the confirmed coordinate and version in this spec's `requirements.md` decisions section before writing code against it.
2. Add `InvestmentThesisClient` interface: `ThesisGenerationResult generate(ThesisGenerationRequest request)`.
3. Add `VertexAiInvestmentThesisClient implements InvestmentThesisClient`: builds the request from `ThesisProperties` (a `@ConfigurationProperties` class binding `GOOGLE_CLOUD_PROJECT`/`VERTEX_AI_LOCATION`/`GEMINI_MODEL_ID` plus the fixed decoding config — `temperature=0.0`, `thinkingBudget=0`, `maxOutputTokens`, `responseMimeType=application/json`, the derived `responseSchema`), calls the SDK client, maps a successful structured response to `ThesisGenerationSuccess`, maps SDK exceptions/timeouts/malformed-JSON to the matching `ThesisErrorCode` via `ThesisGenerationFailure`. Retries only `SCHEMA_VALIDATION_FAILED`/`TIMEOUT`, up to `THESIS_GENERATION_MAX_RETRIES` (default 1), per `requirements.md` → Runtime Contract.
4. Fails fast at application startup (not at first request) if `THESIS_AGENT_ENABLED=true` and `GEMINI_MODEL_ID`/`GOOGLE_CLOUD_PROJECT`/`VERTEX_AI_LOCATION` is blank — a `@PostConstruct` or `ApplicationRunner` validation, matching TRAIN-12's "not a runtime error" framing for the adapted `MODEL_VERSION_UNAVAILABLE` case.
5. Add `ThesisConfigParityTest`: loads `vis-model-training/config/vertex-gemini-v1.json` from the repo root (a resource path relative to the monorepo, or a copied/synced fixture — decide and document which, given `backend/` and `vis-model-training/` are separate Maven/Python projects with no shared build-time file access guarantee; a checked-in JSON fixture under `backend/src/test/resources/vertex-gemini-v1-fixture.json`, manually kept in sync with the Python config and asserted identical via a file-diff step in CI/this phase's validation, is the more robust option — do not assume a relative filesystem read across project boundaries works in every CI environment) and asserts `ThesisProperties`' effective decoding values match: `temperature=0.0`, `thinkingBudget=0`, `maxOutputTokens`, `responseSchema` structurally equal.
6. Add `VertexAiInvestmentThesisClientTest`: every test injects a fake/mocked SDK client (no network call, no real credentials) — success path, `SCHEMA_VALIDATION_FAILED` → retry → success, `SCHEMA_VALIDATION_FAILED` → retries exhausted → `ThesisGenerationFailure`, `TIMEOUT` → `ThesisGenerationFailure`, `INPUT_SCHEMA_INVALID` short-circuits with no retry, no grounding tools present in the built request.

## 4. Deterministic Fallback & Persistence Wiring

1. Add `ThesisGenerationService`: orchestrates `InvestmentThesisClient.generate()` + persistence. On `ThesisGenerationSuccess` with `output.humanReviewRequired()==false` and empty `dataWarnings` → persist `status=READY`. On `ThesisGenerationSuccess` with `humanReviewRequired()==true` or non-empty `dataWarnings` → persist `status=HUMAN_REVIEW_PENDING`. On `ThesisGenerationFailure` → persist `status=FAILED` with the synthetic fallback output (`classification=UNDER_REVIEW`, `humanReviewRequired=true`, empty `bullCase`/`bearCase`, `dataWarnings=[errorMessage]`) — per `requirements.md`'s reconciliation of TRAIN-12's fallback content with the `FAILED` status enum value.
2. Runs on a virtual-thread executor (`Executors.newVirtualThreadPerTaskExecutor()`, wired as a Spring `TaskExecutor` bean) — the generate endpoint dispatches onto it and returns immediately; the executed task performs the Gemini call + persistence.
3. Test: `ThesisGenerationServiceTest` — mocks `InvestmentThesisClient`, asserts each of the three persisted-status branches above, asserts the synthetic fallback output's exact shape on failure, asserts a `HUMAN_REVIEW_PENDING` row is retrievable via the review-queue repository query added in Group 1.

## 5. Endpoints

1. Add `ThesisController` (`it.mazzoni.vis.thesis`, `@RestController`):
   - `POST /api/v1/securities/{symbol}/thesis/generate` — resolves `symbol` → `security_id` (reuse the existing symbol-resolution pattern from `it.mazzoni.vis.security`, do not duplicate it), checks the rate limiter (Group 6), generates a `requestId`, persists an initial `GENERATING` row, dispatches `ThesisGenerationService` on the virtual-thread executor, returns `202 Accepted` with `ThesisGenerationAcceptedResponse(UUID thesisRunId, String status, int pollingIntervalMs, String statusUrl)` (record type, mirroring `it.mazzoni.vis.admin.SeedRunAcceptedResponse`'s exact shape/naming convention).
   - `GET /api/v1/securities/{symbol}/thesis/runs/{thesisRunId}/status` — looks up by `request_id`, 404 if not found or `security_id` mismatch, returns `ThesisRunStatusResponse(UUID thesisRunId, String status, String classification, BigDecimal confidence, Boolean humanReviewRequired, String errorCode, LocalDateTime generatedAt)` (mirroring `SeedRunStatusResponse`'s shape/naming convention).
   - `GET /api/v1/securities/{symbol}/thesis` — `findTopBySecurityIdOrderByGeneratedAtDesc`; `404`/`NOT_GENERATED` body if none exists; otherwise the full thesis DTO plus `stale: boolean` (computed by comparing `generated_at` against the security's latest `ValuationResult`/`ValueScore` `updatedAt`, reusing whichever existing repository already exposes that timestamp — do not add a new query if one already exists for H4C's review-page aggregation).
2. Add `ThesisAdminController`:
   - `GET /api/v1/admin/thesis/review-queue` — `@PreAuthorize` ADMIN-only (match the existing admin-endpoint security-annotation convention in `it.mazzoni.vis.admin`), returns the Group 1 review-queue query results as a paginated list, mirroring the existing alert-queue (G2) response shape where a direct match exists.
3. Test: `ThesisControllerTest`/`ThesisAdminControllerTest` (`@WebMvcTest` or full `@SpringBootTest` slice, matching this codebase's existing controller-test convention) — generate → 202 with a valid `thesisRunId`; status poll on an unknown run → 404; latest-thesis on a symbol with no thesis → `NOT_GENERATED`; latest-thesis `stale=true` when a newer `ValuationResult` exists; review-queue endpoint rejected for a non-ADMIN role; review-queue lists a `HUMAN_REVIEW_PENDING` fixture row.

## 6. Rate Limiting

1. Add `ThesisRateLimiter` (`it.mazzoni.vis.thesis`): `boolean tryConsume(Long userId)` — Redis `INCR` on key `thesis:daily-limit:{userId}:{yyyy-MM-dd}` (UTC date), `EXPIRE` set to seconds-until-next-UTC-midnight on first increment of the day, compares against `THESIS_GENERATION_DAILY_LIMIT` (`@Value`, default 5).
2. Wire into `ThesisController.generate()`: `tryConsume` before dispatching generation; on `false`, return `429`-equivalent (Spring's `ResponseStatusException` with a structured body: `RATE_LIMIT_EXCEEDED`, `limit`, `resetsAt`) — never a generic `500`, never a silently-dropped request.
3. Test: `ThesisRateLimiterTest` — embedded/test Redis (matching however existing Redis-dependent tests in this codebase are set up, e.g. `@Testcontainers` or an in-memory fake, whichever convention already exists — do not introduce a new one), asserts the Nth+1 request within a day is rejected, a request the following UTC day succeeds again.
