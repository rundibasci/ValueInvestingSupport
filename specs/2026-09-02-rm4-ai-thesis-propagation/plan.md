## 2. `ThesisInputBuilder` — precise `netDebtToEbitda` for every sector, plus REIT-field population for REIT securities

## 4. Prompt-content review — REIT-awareness wording (own explicit decision, TA2-style tracking)

Per the roadmap's own framing ("own explicit decision, tracked the way TA2 tracked every prompt-touching decision") and `requirements.md`'s scope confirmation, this phase performs and records the review rather than skipping it.

1. **Review conclusion (recorded in `requirements.md` → Decisions, not just here):** yes, REIT-awareness wording is needed. Today's prompt has no field-specific guidance beyond the generic evidence-field list and Rule 6 ("A high dividend yield alone is not evidence of dividend safety") — nothing tells the model that a REIT's GAAP net income (and hence any GAAP-derived signal reaching it indirectly through `dataQuality`/`deterministicWarnings`) is structurally depreciation-suppressed, which risks the model treating a REIT's *absence* of strong `earningsTrend`/`marginOfSafetyPercent` signal as a red flag it has no FFO/AFFO context to weigh against, when `ffoPerShare`/`affoPerShare`/`affoPayoutRatio` are non-null.
2. Add one new rule to `system-prompt-v3.txt`'s numbered rules list (both copies), inserted after the existing Rule 6 (dividend-yield-alone caveat) since it is the closest existing precedent for "don't over-read one metric in isolation": **"When `ffoPerShare`, `affoPerShare`, `priceToFfo`, `priceToAffo`, or `affoPayoutRatio` are non-null, this security is REIT/real-estate-classified and its net-income-derived signals (e.g. a weak or absent `earningsTrend`) may reflect non-cash real-estate depreciation rather than deteriorating operating performance — weigh FFO/AFFO-based evidence fields for this security's cash-generation and dividend-sustainability claims instead of, or alongside, GAAP-earnings-only reasoning."** Renumber subsequent rules accordingly (existing Rule 7 onward shifts down by one) — update both copies identically.
3. **Explicitly not changed:** the `classification`/`confidence`/output JSON shape, the `humanReviewRequired` trigger rules (Rules 9-10 in the current numbering), and every other existing rule — this is a strictly additive rule insertion, not a rewrite. `ThesisResponseSchema`/`thesis-output.schema.json` are untouched by this group (only Group 3 touches them, for the `evidenceFields` enum).
4. No automated test can verify prompt *content* quality (no eval harness exists in this codebase for prompt wording changes — `vis-model-training`'s benchmark/scenario suites (TRAIN-03/04) are a heavier evaluation pipeline explicitly out of scope for a single-rule prompt edit, confirmed by reading `specs/roadmap.md` → Group TRAIN's own scope). Verification is: (a) the live Vertex smoke test in Group 6 below produces a plausible REIT thesis that doesn't flag depreciation-suppressed earnings as an unqualified red flag, read manually and quoted in `validation.md`; (b) `ThesisConfigParityTest` and the Group 3 tests confirm the prompt's allowed-fields list and the enforced schema stayed in sync.
